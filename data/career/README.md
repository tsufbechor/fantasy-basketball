# NBA career season data

Rebuild with `./.venv/bin/python scripts/collect_career_data.py` from the project root. Dependencies are isolated in `.venv`; install with `./.venv/bin/pip install -r requirements-career.txt`.

The tracked universe is the union of the three saved Hashtag Basketball HTML snapshots in the project root. The first file's selected dataset is 2024–25, despite its filename. Full-name desktop links are used once per Hashtag ID; mobile duplicates are ignored. The 2026–27 snapshot contributes to the player universe only. It is never treated as historical stats.

Historical source: `nba_api`'s `LeagueDashPlayerStats`, `SeasonType=Regular Season`, queried season-wide for Base and Advanced measures, from 1996–97 through the latest completed regular season (on 2026-10-08, this was 2025–26). The default end season follows the local calendar year and NBA season cycle; update the `END` calculation if the NBA calendar changes materially. Every response is cached as JSON under `data/career/raw/`; completed caches are reused on rerun. Retries are bounded to three attempts with increasing pauses, and calls are throttled by 1.5 seconds. Failed seasons are recorded in `collection_errors.json` and coverage is incomplete until rerun succeeds.

`player_mapping.csv` maps Hashtag IDs/names to NBA IDs by exact normalized full-name match (Unicode accents and punctuation normalized). No fuzzy matches are accepted. Edit a row's `nba_player_id` and set `mapping_status` to `manual` to supply an explicitly reviewed alias, then rerun. Mapping is by NBA ID, not display name, so name changes do not split career rows.

`player_seasons.csv` has one row per mapped NBA player and season. Base stats prefer a source-provided TOT season aggregate when present. If the source returns team stints without TOT, additive fields are summed and team abbreviations are joined. Advanced rate fields including USG_PCT are minutes-weighted across stints. Percentages other than usage are retained only when supplied on a full-season row; no stint percentages are averaged. LeagueDashPlayerStats reports minutes in minutes, totals as counts, percentages on 0–1 scale except USG_PCT which is converted below. Per-game minutes/FGA/FTA are derived from season totals divided by GP. Rows are provided by season; absent player-seasons are not zero-filled. `usage_pct` is source USG_PCT converted from the NBA API's 0–1 representation to 0–100. On multi-team seasons, USG_PCT is minutes-weighted across the stint rates because LeagueDash provides no total-season aggregate; this is a practical approximation, not an exact re-computation from team possession totals. The NBA usage definition estimates the percentage of team plays used by a player while on court, accounting for FGA, FTA, turnovers and minutes; it is not share of team FGA.

`coverage_report.csv` provides mapping status and observed first/last source seasons and gaps. A player's continuous span between first and last observed seasons is the current expected interval; seasons outside that interval are not assumed to be career seasons. This cannot prove complete career coverage for players whose first endpoint season predates 1996–97. Data before 1996–97 is not served by the tested LeagueDash endpoint; any such player coverage is necessarily incomplete. Collection errors, unmapped names, and missing fields must be reviewed before treating the dataset as complete.

Limitations: NBA Stats is an undocumented, access-controlled endpoint and can fail or change schema. LeagueDashPlayerStats provides no explicit TOT row in tested seasons, so additive fields are summed across team rows and advanced percentage rates are minutes-weighted. Validate unusual multi-team seasons against the raw source. Cached JSON preserves returned source records. No Basketball Reference scraping or paid BALLDONTLIE access is used.

For mapped players with multiple-team seasons or gaps between observed seasons, the collector requests `PlayerCareerStats` and caches each player response under `data/career/raw/player_career_<NBA_ID>.json`. It supplies the full team list, games started, and independent season coverage. LeagueDash remains the source for season aggregate stats; the player endpoint resolves teams and verifies career seasons. `team_enrichment_errors.json` records failures in this optional lookup. LeagueDash Base does not return GS, so games started remain blank unless supplied by a supplemental endpoint; blanks are not treated as zero. FG% and FT% are recomputed as combined FGM/FGA and FTM/FTA to correctly represent the full-season aggregate. A percentage is blank when its denominator is zero.

## Last collection (2026-10-08)

The snapshots contained 200, 297, and 300 distinct full-name entries; their union was 366 Hashtag player IDs. There are 356 mapped NBA IDs (349 exact normalized-name matches and 7 manually reviewed aliases) and 10 unmatched names. The outputs contain 2,209 unique player-season rows from 2003–04 through 2025–26. All 30 season-wide queries succeeded, and all 142 requested player-career coverage/team lookups succeeded. Coverage has 214 players with no gaps between observed seasons, 120 with complete spans checked against PlayerCareerStats, 22 whose internal gaps have no NBA career-season record in PlayerCareerStats, and 10 unmapped names. No player-season was expected by PlayerCareerStats but missing from the season-wide data. `coverage_report.csv` gives expected versus retrieved season counts, seasons with no PlayerCareerStats record inside a career span, season-wide gaps where a career record exists, and failed retrievals per player.

Last validation: `./.venv/bin/python scripts/validate_career_data.py` passed. Blank optional values: games started 1,070 (LeagueDash does not provide GS; it is present for players queried through PlayerCareerStats), FG% 2 and FT% 13 (zero-attempt denominators).
